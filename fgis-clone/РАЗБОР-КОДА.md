# Разбор кода по строкам

Проект: `C:\Users\Districk\Desktop\123\fgis-clone`

Как читать: слева номер строки (как в редакторе), справа — что эта строка делает. Группы
служебных строк (импорты, пустые, закрывающие скобки) описаны одной записью, всё остальное —
построчно.

Порядок разбора — как код реально исполняется:

1. `server.py` — точка входа, HTTP-сервер и все маршруты.
2. `pov.py` — разбор HTML поверок.
3. `fgis_client.py` — запросы к ФГИС и нормализация данных.
4. `sniff.py` — вспомогательная диагностика через браузер.
5. `web/src` — React-интерфейс.

# 6. Сквозной сценарий: что происходит при клике «Найти»

1. Пользователь жмёт кнопку → `Toolbar` вызывает `onSearch`.
2. В `App.jsx` это `() => setPage(1)` — меняется состояние `page`.
3. `useEffect` (строка 51) видит новую зависимость и запускает `searchRegistry`.
4. `api.js` собирает `/api/search?reg=pov&q=...&page=1&rows=20&year=...&filters={}`.
5. `server.py` в `do_GET` попадает в ветку `/api/search` (181), видит `reg == "pov"` (188).
6. Вызывает `fc.pov_list(...)` → `fgis_client.py` запрашивает HTML страницы поверок.
7. `pov.py` разбирает HTML: колонки из `<thead>`, строки из `<tbody>`.
8. Сервер отдаёт JSON `{columns, items, total}`; фронт раскладывает его по состояниям.
9. `ResultsTable` рисует заголовки из `columns` и строки из `items[i].cells`.

Клик по строке: `onOpen(item)` → `openCard` → `getCard(reg, id)` → `/api/card` → `fc.pov_card` →
`pov.parse_card` → JSON с секциями → `CardPage` рисует панели.

Кнопка «Выгрузить»: `window.location.href = csvUrl(...)` → браузер идёт на `/api/export` →
сервер проходит 5 страниц по 20 записей, склеивает CSV с BOM и отдаёт файл.

# 8. Что я бы поправил дальше (честный список)

1. **Поиск по строке для поверок не проверен**: параметр `search` может игнорироваться сайтом —
   тогда нужен фильтр через модалку (её отправку надо снять тем же `sniff.py`).
2. **`pageSize` для поверок** тоже не подтверждён: 20 работает точно, 50/100 — нет.
3. **Фильтры модалки** для поверок пока не применяются: сервер их принимает, но в `pov_list`
   они не уходят (там только год и сортировка).
4. **CSV для поверок** ограничен 5 страницами (100 записей) — для больших выгрузок нужен
   обход с прогрессом.
5. **Нет тестов**: сейчас проверка ручная (смоук-тесты я гонял отдельными скриптами).
6. **`api_config.json`** — глобальное состояние на диске; при нескольких запусках может мешать,
   лучше хранить в памяти процесса.
