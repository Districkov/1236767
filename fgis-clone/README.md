# Локальное зеркало ФГИС (fgis.gost.ru)

Копия интерфейса «Результаты поверок СИ»: React + Vite на фронте, небольшой Python-сервер,
который берёт данные **напрямую из JSON-API сайта** (без парсинга отрендеренных страниц).

## Запуск

```bash
cd fgis-clone
python server.py          # http://127.0.0.1:8017
```

Готовая сборка фронта уже лежит в `static/` — Node нужен только если правите интерфейс.

Режим разработки (с горячей перезагрузкой, запросы к `/api` проксируются на 8017):

```bash
python server.py                    # терминал 1
cd web && npm install && npm run dev # терминал 2 → http://127.0.0.1:5173
npm run build                        # пересобрать в ../static
```

## Диагностика API

```bash
python fgis_client.py probe            # быстрая проверка: отвечает ли API вообще
python fgis_client.py probe --deep     # глубокая: реальные ответы API, пути из JS сайта,
                                       #           и автоподбор рабочего набора параметров
python fgis_client.py search 4 "мультиметр"   # поиск в реестре поверок
python fgis_client.py card 4 98765432         # карточка записи
```

`probe --deep` — главный инструмент: он пробует эндпоинт с разными наборами параметров
(`rows/page`, `page/size`, `limit/offset`, с годом и без), печатает первые 240 символов ответа
и, если какой-то вариант вернул записи, сохраняет его в `api_config.json`. После этого
`server.py` сразу использует найденный вариант — без правки кода.

Результаты пишутся в `probe_report.json` и `probe_deep.json`.

## Структура

```
fgis-clone/
├── server.py              локальный сервер: /api/search, /api/card, /api/export, статика, кэш
├── fgis_client.py         клиент к API ФГИС + диагностика + нормализация
├── web/                   исходники интерфейса (React + Vite)
│   ├── index.html
│   ├── vite.config.js     base=/static/, сборка в ../static
│   └── src/
│       ├── App.jsx        состояние: год, поиск, страница, фильтры, карточка
│       ├── api.js         запросы к /api + демо-данные на случай недоступности
│       ├── helpers.js     колонки, подписи полей, форматирование дат
│       ├── styles.css     стили под макет
│       └── components/    Header, Hero, YearTabs, Toolbar, MetaBar,
│                          ResultsTable, FilterModal, CardPage
├── pov.py                 разбор HTML раздела поверок (список и карточка)
├── sniff.py               снятие разметки и сетевого лога через headless-браузер
├── static/                собранный фронт (index.html + assets) — отдаёт server.py
└── cache/                 кэш ответов (создаётся автоматически)
```

Служебные файлы (`cache/`, `api_config.json`, `__pycache__/`, `netlog.json`, `_browser_profile/`)
создаются при работе и в репозиторий не нужны — они в `.gitignore`.

## Что умеет интерфейс

- вкладки по годам (Все, 2026…2010, до 2010);
- поиск по строке и модальный фильтр на 11 полей (организация, рег. номер, тип, заводской номер,
  диапазоны дат поверки и срока действия, свидетельство, наклейка, пригодность);
- таблица с сортировкой по клику на заголовок, пагинация, переключение «20/50/100 на страницу»;
- карточка записи блоками: «Сведения о результатах поверки СИ» / «Сведения о поверке» / «Средства поверки»;
- выгрузка в CSV (до 500 записей, разделитель `;`, BOM для Excel).

## API ФГИС, который реально используется

Взято из их бандла `app-bundle.js` (base — `/fundmetrology`):

| Что | Запрос |
|---|---|
| дерево реестров | `GET /api/tree` |
| описание полей реестра | `GET /api/registry/{id}/fields` |
| список записей | `GET /api/registry/{id}/data?pageNumber=1&pageSize=20&orgID=unset&filterBy=<поле>&filterValues=<значение>&sortBy=<поле>&sortValues=asc` |
| карточка записи | `GET /api/registry/{id}/items/{itemId}/plaindata` |
| реестр поверок | `GET /api/povregistry` |

`id` реестра ≠ номер в URL: `/api/registry/4` — это «Утверждённые типы средств измерений»,
а реестра «Поверки» в `/api/tree` вообще нет — у поверок отдельная ветка (`/api/povregistry`, `/api/povdata`).

Поэтому клиент не гадает, а перебирает источники списка (`LIST_SOURCES`) и запоминает рабочий
в `api_config.json` (`{"source_name": "...", "registry": "..."}`). То же самое делает `server.py`
при старте: печатает в консоль, какой источник данных выбран.

## API локального сервера

| Метод | Что делает |
|---|---|
| `GET /api/search?reg=4&q=&page=1&rows=20&year=2026&filters={"org":"..."}` | список записей реестра |
| `GET /api/card?reg=4&id=<id>` | карточка записи |
| `GET /api/export?reg=4&q=&filters={}&pages=5` | CSV |
| `GET /api/probe` | диагностика доступных эндпоинтов |
| `GET /api/registries` | список реестров |

## Поверки: разбор HTML, а не API

Раздел «Результаты поверок СИ» (`/fundmetrology/cm/results`) рендерится на сервере —
XHR нет, данные лежат в разметке. Поэтому клиент не ходит в API, а разбирает HTML:

| Что | Как |
|---|---|
| список | `GET /fundmetrology/cm/results?page=2&activeYear=2026&sort=org_title\|asc` → `pov.parse_list()` |
| карточка | `GET /fundmetrology/cm/results/{id}` → `pov.parse_card()` (секции `<h3>` + пары «подпись — значение») |

Колонки берутся из `<thead>` и сопоставляются с ключами (`org_title`, `mit_number`,
`verification_date`, `sign_cipher`, `applicability` …), поэтому таблица совпадает с сайтом.
«Пригодность» на сайте — иконка `<i class="fas fa-check">`, парсер превращает её в `✓`.

Ссылка на карточку в приложении: `http://127.0.0.1:8017/?open=1-568493097`.

Вспомогательные скрипты:

```bash
# снять разметку страницы (создаст list.html и *_urls.txt — временные файлы)
python sniff.py https://fgis.gost.ru/fundmetrology/cm/results --save list.html

# проверить разбор на сохранённой странице
python pov.py list list.html
python pov.py card dom.html
```

`sniff.py` запускает Edge в headless-режиме с `--log-net-log` и `--dump-dom`, сохраняет
разметку и список запросов — им и выяснилось, что API у поверок нет.

## Важное ограничение

`fgis.gost.ru` отдаёт данные не всем адресам: с зарубежных IP TCP/TLS-хендшейк падает по таймауту
(проверено напрямую и через внешние прокси). Нужен российский IP или VPN — иначе интерфейс
покажет демонстрационный набор и текст ошибки.

Данные ФГИС открытые, но сервер общий: клиент кэширует ответы и делает паузы при выгрузке.
Для массового сбора лучше сначала уточнить лимиты у оператора ФГИС.
